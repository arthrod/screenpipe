### 3. Grader pass/fail thresholds are explicit — yes, and robust
- Shipped grader (cases.json `grader.command`): pass = cargo exit 0 (all 7 outcomes), anything else fails, bounded at 180 s (`spawnSync` timeout `180_000` at calibrate :26; bun test timeout 200 s).
- Calibration `fails()` (:32) requires exit status exactly 101 **and** `'test result: FAILED.'` in stdout — a compile error also exits 101 but prints no test summary, so a drifted anchor can't be mistaken for a behavioral rejection.
- `'running 7 tests'` (:29) guards against a vacuous pass (mistyped filter → 0 tests → exit 0).
- `classifyGraderError` (grader-outcome.mjs) separates setup diagnostics (`command_unavailable` 126/127, process errors) from behavior results.
- Empirical results (all commands run this session, in `/tmp/eval-ref-check`): reference → `test result: ok. 7 passed; 0 failed`, exit 0. Parent (`5ce7edfc`) → `test result: FAILED. 5 passed; 2 failed`, exit 101, the two failures being exactly the duplicate-inventory outcomes. `equivalent` mutation (Vec-based dedup) → `7 passed`, exit 0 (grader not overfit to the oracle implementation). `name-only` mutation → `FAILED. 4 passed; 3 failed`, exit 101.

Static support for the not-run controls: every mutation anchor used by `replace()` (which asserts `text.split(from)` has length 2, calibrate :19) occurs **exactly once** in device.rs at oracle_ref (python3 exact substring counts): the dedup block, `seen.insert(device.clone())`, the cache-validity condition, `'    Ok(devices)\n}'`, `'        topology_generation,\n    });'`, and `'    let mut devices = enumerate().await?;'`. `Cargo.lock` is byte-identical between base_ref and oracle_ref (same sha256), so the parent run shares the dependency build.
