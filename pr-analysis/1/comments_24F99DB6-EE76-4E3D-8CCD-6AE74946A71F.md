**[P3]** `crates/screenpipe-engine/src/automation_flows/health.rs:402` — A failed run can be permanently invisible to notifications due to timestamp mismatches. Two paths: (a) `stopped_at.and_then(instant).is_none_or(|at| at < since)` (`health.rs:401-404`) silently skips — every check, forever, without recording anything — any failed run whose `stoppedAt`/`startedAt` is missing or unparseable; (b) the watermark `since` comes from `last_check_at`, stamped with the *engine's* clock (`health.rs:269,438`), but it is compared against `stoppedAt` stamped with *n8n's* clock. With any constant skew δ between the two (Docker VM clock drift after host sleep, or a remote n8n), a run that stops within δ after a watermark has a timestamp that stays below every future watermark, so it is never notified. Recording the watermark as the newest `stoppedAt` actually observed (n8n's own clock), or notifying runs whose timestamp cannot be parsed, would close both holes; today a missed run leaves no trace in `pendingNotifications` either.
