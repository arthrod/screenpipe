## Findings (details in the posted comment)

1. **P2 — timezone-sensitive test** `flows-tab.test.tsx:790` asserts `Oct 17` for a `02:05Z` fixture
   (line 777); reproducible: fails at UTC-3 and further west (proven above; sibling test at :280-281
   deliberately picks 09:05Z and documents why). CI (UTC) will stay green, so this silently breaks local runs
   for roughly half the world's timezones.
2. **P2 — delete/restore reloads the whole list through "loading"** (flows-tab.tsx:90-94 + common.tsx:56):
   one row's action blanks the entire tab, closes sibling confirmations, and if the post-action reload fails
   a *successful* delete renders as the full error screen. The hook's own `replace` (common.tsx:101-108) and
   the returned `Flow` from `api.restore` (api.ts:362-368, discarded at flows-tab.tsx:92) exist for this.
3. **P3 — `RestoreButton` sets `busy` false only in `catch`** (flows-tab.tsx:158-167); works today only
   because the row unmounts during the reload. Asymmetric with `OpenButton`'s `finally` (common.tsx:209-211).
4. **P3 — `FlowsErrorMessage` generic titles are list-plural** (common.tsx:277-282) but the component also
   serves the single-Flow Review Screen (flow-review.tsx:61): "The Flows could not be loaded" for one Flow;
   conversely a list-level `not_found` would say "This Flow no longer exists in n8n".
5. **P3 — "Open Connections" swallows rejections** (common.tsx:251, 267 `void api.openN8nConnection()`),
   inconsistent with `OpenButton`'s `role="alert"` failure copy (common.tsx:225-229); `emit` can reject (api.ts:420-422).
6. **P3 — `useFlowsLoad` latent fragility**: `loadRef.current = load` during render (common.tsx:44-45) and no
   guard for a synchronously-throwing `load`, which would leave `pending.current` set forever and permanently
   block background reads (common.tsx:52-61). All three current call sites are async functions
   (flows-tab.tsx:48, health-banner.tsx:20, flow-review.tsx:43), so latent only.

## What I checked and consider sound (focus: state machine, keys, prop drilling, no invented data)

- **Nothing invents data.** `FlowRow` renders exactly the `FlowSummary` fields (id/name/status/lastExecution,
  api.ts:22-27); `flow.lastExecution?.status === "error"` and `=== "running"` (flows-tab.tsx:121, 141) are both
  members of the `LastExecution["status"]` union (api.ts:17-20); `STATUS_LABEL` covers all five `FlowStatus`
  values (labels.ts:7-14), so `STATUS_LABEL[status]` (common.tsx:161, flows-tab.tsx:78, 82) is never undefined;
  `lastRunLabel(null)` → "Never run" (labels.ts:50-53). Group headers count real group lengths only.
- **Keys** are correct: `key={flow.id}` (flows-tab.tsx:86) is unique because `groupOf` (flows-tab.tsx:24) is a
  total mapping placing each flow in exactly one group; `key={status}` (flows-tab.tsx:76). In `flow-learned-from.tsx:77`
  the `key={`${index}-...`}` is index-based but that file is outside my slice.
- **Race logic of `useFlowsLoad` traced**: latest-counter + single pending slot (common.tsx:46-60) correctly drops
  stale reads, skips background reads while one is in flight, keeps `ready` state on background failure
  (common.tsx:69-74), and self-heals from `error` via background success (common.tsx:63-65). Covered by tests
  (flows-tab.test.tsx:1104-1195). No in-flight request is aborted on unmount/key change (cleanup only invalidates
  state, common.tsx:80-83) — acceptable for local calls, noted as latent in finding 6.
- **Prop drilling** is `api` three levels deep (FlowsTab→FlowList→FlowRow→FlowDelete, flows-tab.tsx:29, 41, 89, 115)
  with a default to the real client — this is the deliberate single seam (api.ts:5-8) and what makes the test
  `fakeApi` (flows-tab.test.tsx:39-63) possible. Not a problem.
- **a11y** is deliberate: square-only status keeps a `sr-only` label (common.tsx:139, 160-162), list `aria-label`
  (flows-tab.tsx:82), named Restore button (flows-tab.tsx:175); failed runs are never color-only
  (flows-tab.tsx:133-137, tested at flows-tab.test.tsx:111-131).
- **Security**: no secrets or dangerous sinks in either file; the activation credential lives in api.ts (other slice).
