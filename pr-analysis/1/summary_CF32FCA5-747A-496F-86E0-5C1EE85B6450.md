## Findings (files reviewed at `origin/main` — not PR content)

### F1 — P2: Anthropic fixture never exercises cache-token fields, so the grader cannot catch cache-math regressions

Focus area "math on cache/input tokens". The fixture's usage payloads only ever carry `input_tokens`/`output_tokens` (`graders/anthropic-json-usage.fixture.ts.txt:22,30-36,40-45`). The oracle maps `total_tokens = input + output` and never reads or forwards cache fields (`packages/ai-gateway/src/providers/anthropic.ts:384-387` at `3ccae296`). Real Anthropic non-stream usage includes `cache_creation_input_tokens` / `cache_read_input_tokens`; an evaluated implementation that computes `total = input + output + cache_read`, or that crashes on the extra fields, passes all 12 grader tests.

`cases.json`'s prompt declares the boundary ("uncached input/output usage … total_tokens is their sum"; "prompt-cache accounting … outside this task"), so the oracle is in-scope-correct — but a grader whose payloads never contain the fields cannot *enforce* that declared boundary (spec/grader mismatch is exactly what calibration exists to prevent). Cheap fix: one loop iteration whose payload has cache fields present, asserting prompt/completion/total stay `input`/`output`/`input+output`. Mitigation: the gate is `advisory` (`cases.json:393` region for this case).

### F2 — P3: the Anthropic `equivalent` control silently relies on Bun not typechecking

`calibrate-anthropic-json-usage.test.js:23` renames `formatResponse` → `encodeCompletionReply` **only inside the oracle file**. `formatResponse` is a member of the `AIProvider` interface (`packages/ai-gateway/src/providers/base.ts:11` at `7f4f149`), which the class `implements` (`anthropic.ts:16` at `3ccae296`). Under `tsc` the renamed file would fail ("missing interface member") and the control would report `error` instead of the expected `pass`. It passes today only because the grader command is `bun --no-env-file test` (Bun strips types without checking, per `cases.json` `grader.command`). A one-line comment on the control would save the next person who changes the grader command a confusing mystery.

### F3 — P3: ~45 lines of calibration harness duplicated, supporting-file list hardcoded

`calibrate-anthropic-json-usage.test.js:33-59` and `calibrate-openrouter-stream.test.js:31-57` are near-identical (temp dir, pinned supporting checkouts, spawn with scrubbed env, `classifyGraderError`, receipts). Both hardcode `['packages/ai-gateway/src/providers/base.ts', 'packages/ai-gateway/src/types.ts', 'packages/ai-gateway/src/providers/vertex.ts']` (anthropic `:37`, openrouter `:35`). If an oracle ever imports another module, the temp-dir import fails and every control flips to `error` — a confusing failure mode a shared helper (or an import-derived file list) would localize.

### F4 — P3: stream fixture validates SSE *emission*, not ingestion — fine per scope, but know the limit

The fixture mocks the SDK above the transport (`graders/openrouter-stream.fixture.ts.txt:6-15`), so OpenRouter's real wire quirks (`: OPENROUTER PROCESSING` keep-alive comments, `event:`/`id:` lines, multi-line `data:` fields) are never decoded; `collect()`'s parser (`:26`) only re-parses the provider's own output. The case prompt explicitly scopes "SDK transport" out — consistent, just worth documenting. Minor sub-gap: no `usage: null` mid-stream chunk (real OpenRouter sends usage only on the final chunk); a passthrough that dropped `usage: null` would still pass. Harmless information-wise.
