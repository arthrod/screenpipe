# Reviewer slice: coverage docs + agent docs (PR #1)

Slice: `docs/COVERAGE.md`, `docs/agents/domain.md`, `docs/agents/issue-tracker.md`,
`docs/coverage/CORE.md`, `docs/coverage/core-engine-map.json`.

## What the PR actually changes in this slice

`git diff origin/main...HEAD` on the five slice files shows only two changed
files, both new:

- `docs/agents/domain.md` — new, 8 lines: points agents at root `CONTEXT.md` as
  the Automation Flows glossary (`Automation Flow`, `Detected Task`), with a
  conditional "if `GLOSSARY.md` or `docs/adr/` exist, follow them".
- `docs/agents/issue-tracker.md` — new, 14 lines: tickets are markdown files
  under `.scratch/<topic>/`; skills saying "publish to the issue tracker" write
  there.

`docs/COVERAGE.md`, `docs/coverage/CORE.md`, and
`docs/coverage/core-engine-map.json` exist on origin/main and at HEAD but have
**zero diff** in this PR — the PR does not touch them, despite adding large
amounts of engine code they are supposed to describe. That turns out to be the
slice's main problem (below).

### 3. Coverage docs vs map JSON — the CI gate fails at this PR's head (main finding)

Ran the exact command CI runs (`.github/workflows/style.yml:219-220`,
`bun run coverage:all:check`) from `apps/screenpipe-app-tauri`:

- e2e stage: **passed** ("Coverage report is up to date: e2e/COVERAGE.md").
- core stage: **FAILED**. Generator output (`generate-core-engine-coverage-report.ts:920`,
  "Invalid core coverage manifest") — 7 engine files have no mapped suite:
  - `crates/screenpipe-engine/tests/automation_flows_test.rs`
  - `crates/screenpipe-engine/src/automation_flows.rs`
  - `crates/screenpipe-engine/src/automation_flows/health.rs`
  - `crates/screenpipe-engine/src/flow_checks.rs`
  - `crates/screenpipe-engine/src/n8n_nodes.rs`
  - `crates/screenpipe-engine/src/routes/chatgpt_proxy.rs`
  - `crates/screenpipe-engine/src/routes/cloud_proxy.rs`
- unified stage: never ran (script exited at core stage). Reported as not run.

Attribution to this PR (all verified by running, not assumed):

- `git cat-file -e origin/main:<file>`: 6 of the 7 files are new in this PR.
  `cloud_proxy.rs` pre-exists but had 0 `#[cfg(test)]` blocks on origin/main
  vs 1 at HEAD — this PR added its tests, which is what newly requires mapping.
- Re-ran the core check on a throwaway worktree of origin/main
  (`git worktree add /tmp/swp-main-review origin/main`, then
  `bun ../../docs/coverage/scripts/generate-core-engine-coverage-report.ts --check`):
  **passes** ("Core coverage report is up to date"). Worktree removed after.
  So the failure is introduced by this PR, not inherited.
- Scale: 143 `#[test]`/`#[tokio::test]` attribute lines across the 7 files at
  HEAD (grep counts: 107 + 3 + 2 + 9 + 1 + 15 + 6).
- The map (`docs/coverage/core-engine-map.json`) has zero mentions of
  automation_flows / flow_checks / n8n_nodes / chatgpt_proxy / cloud_proxy;
  its 12 `screenpipe-engine` suites and 11 `criticalFlows` ids contain nothing
  for Automation Flows. Enforcement is on (`enforceMappedIntegrationTests` /
  `enforceMappedSourceTests`: true, map lines 8-9).

### 4. "Regenerated, not hand-edited (keys sorted)" — premise doesn't match this file

Nothing regenerates `core-engine-map.json`. `docs/coverage/README.md:26`
describes it as a "declarative map"; the generator only reads it
(`generate-core-engine-coverage-report.ts:19`) and writes `CORE.md` (line 20).
Its top-level keys are not sorted — `version, platforms,
enforceMappedIntegrationTests, enforceMappedSourceTests, trackedCrates,
criticalFlows, suites` (`jq keys_unsorted`) — that is hand-authored structural
order. So "keys sorted as proof of regeneration" is not a verifiable property
here; the verifiable property is CI's validation + report regeneration, which
is exactly what fails.

### 5. Stale claims in COVERAGE.md / CORE.md

`docs/COVERAGE.md:39-49` (core snapshot) and `docs/coverage/CORE.md:7-14` are
internally consistent with each other and with the 37-suite map (37 suites,
394 files, 3869 active blocks, 181 ignored, 3194.4 weighted points; matching
per-platform rows). But at this PR's head they are stale: they cannot include
the 7 new test-bearing files because the map doesn't know them, and the
generator throws during manifest validation
(`generate-core-engine-coverage-report.ts:918-920`) before it can regenerate
either report. So both dashboards omit ~143 new test blocks and the PR's
flagship feature has no critical-flow entry ("Flows: 11", "Critical score
100%" predate Automation Flows).

## Fit within the whole PR

The PR's center of mass is Automation Flows (engine routes/lifecycle, n8n
nodes, app UI, chat skill). The two new `docs/agents/*.md` files are the
context-packaging piece of that work (per the hackathon history, deliberate).
The coverage docs slice is where the PR under-delivers: it adds thousands of
lines of new engine code and tests without extending the behavioral coverage
map that CI enforces, so the docs gate this PR touched-but-didn't-update now
fails.

## Risks / quality issues

- **P1 — CI-blocking**: `coverage:all:check` fails at HEAD (evidence above).
  Fix: add suites (and a critical flow) for the new engine files to
  `docs/coverage/core-engine-map.json` following the existing hand-authored
  format, then regenerate both reports with `bun run coverage:all` and commit
  the results.
- **P2 — stale dashboards**: `docs/COVERAGE.md` and `docs/coverage/CORE.md`
  snapshots exclude the new code until the map is fixed and reports
  regenerated (same fix as the P1).
- **P3 — docs/agents discoverability**: only CLAUDE.md points at the new
  files; AGENTS.md's "Read on demand" list does not.
