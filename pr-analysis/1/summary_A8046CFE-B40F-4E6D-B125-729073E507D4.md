## How it fits the PR

This file is the engine-side HTTP contract suite for Automation Flows; my range pins the PR's core safety rules at the API boundary: "only the user turns a Flow on" (no credential → no publish), "the chat never picks n8n credentials" (strip-then-rewire), "nothing runs without review" (chat edits flip active flows to `needs_review`, and an n8n-refused edit leaves them off), and "switching off never loses the email being processed" (the exact rehearsal-3 regression). It complements the UI slices: these are the guarantees the Review Screen UI is built on.

## Risks / issues found

1. **P2 — test gap, update-path credentials for a *new* node.** `chat_update_keeps_the_users_credentials_and_never_takes_the_chats` (2424–2465) covers name+type-matched restore on PUT; `chat_create_cannot_wire_the_users_n8n_credentials` (2801) covers create. No test covers **PUT with a brand-new node that carries a chat-supplied credential id** — the exact hole this PR's rule exists to close. The implementation is correct today (`keep_user_credentials` at `automation_flows.rs:976-997` strips unmatched nodes, then `check_and_wire` re-wires), but a regression on the update path would ship untested. Posted as a comment.
2. **P3 — media-type sample pins only ticket-04-era routes.** `state_changing_routes_take_only_json_requests` (2025–2043) samples create/from-task/PUT/activate/deactivate. The guard is one `.layer(middleware::from_fn(require_json))` placed last in the router builder (`automation_flows.rs:289-294`); a route appended after that `.layer(...)` call, or in another router, would silently bypass it and this test would stay green. Adding the newest POST route (e.g. `/:id/runs/:run/retry`) to the sample pins the layer over later-added routes. Posted.
3. **P3 — `add_auto_label` fixture misdescribes its node.** The helper (2160–2169) puts the sentence « Chaque ticket créé reçoit aussi l'étiquette auto. » and `parameters.labels` on the **Gmail trigger** node ("New support email"), which receives email and creates nothing; `labels` is also not a real parameter of that node (not present in the committed workflow JSON). `flow_checks` doesn't validate parameter keys, so it passes, but the fixture normalizes a node-sentence/node mismatch — the exact thing design rule 5 (one-sentence explanation that matches the node) forbids, and other helpers get copied. Posted.
