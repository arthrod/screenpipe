per-ticket build/verification records for round two of Automation Flows: what to build, status,

## What this slice is in the whole PR

The PR is the entire round-two feature drop (engine Flow lifecycle, app Review Screen, workflows-ui
theming, n8n nodes, chat skill, demo tooling). These six docs are the paper trail for tickets 01–06;
later tickets (07–17, not my slice) and the `coverage.md` index sit beside them. A wrong claim here
sends the next verifier (human or agent) after strings, tests, or behaviours that do not exist, so I
checked each doc's claims against the code and ran the test files that are cheap to run.

## Cross-cutting finding (posted)

Every one of the six docs quotes user-visible strings in French — « Voir le graphe », « Tâche répétitive
détectée », « Notification non affichée », « Démo non lancée », « Supprimer définitivement »/« Annuler »,
« Trouver une automatisation », « Créer l'automatisation » — but the shipped UI has **no French
anywhere**: grep across `apps/screenpipe-app-tauri/{components,lib}` and `packages/workflows-ui/src`
finds French only in comments and in tests asserting a French label is *absent*
(`pipe-store-flows-tab.test.tsx:148-149`). The real strings are English ("Open in n8n"
`flow-graph.tsx:9`, "Repetitive task detected" `detected-task.ts:32`, "Notification not shown"
`demo-shortcut.ts:60`, "Demo not started" `demo-shortcut.ts:56`, "Delete for good"/"Cancel"
`flow-delete.tsx:57-68`, "Create automation" `workflows-view-theme.test.tsx:153`). The live-check
instructions in these docs direct a human to look for labels that do not exist, so the records mislead
the next verifier even where the behaviour they describe is real.

## Quality assessment

The docs are unusually verifiable — named tests, concrete numbers, per-claim checkboxes — and most
claims checked out exactly (issues 01, 04, 05, 06 nearly fully; 03's mechanics entirely). The failures
are concentrated in issue 02, where the record describes work that is not in the tree (the three
dialogs) and overstates the token conversion, plus stale counts (02: "5 passed" vs 3; 03: "5 new" vs 8)
and one stale byte size (05). Nothing in this slice is a product-code defect; the risk is process:
the "Tests run" sections were not updated after the code moved on.
