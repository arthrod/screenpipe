**P3 — `apps/screenpipe-app-tauri/components/automation-flows/api.ts:133-146` — `stageCaptures` re-implements `stageScreenshots`, and the copies can drift apart.**

`EMBEDDED_IMAGE` and `stageCaptures` here are a character-for-character copy of `isEmbeddedScreenshot` + `stageScreenshots` (`packages/workflows-ui/src/screenshots.ts:4-20`), including the `jpeg|png|webp` restriction and the dedupe-by-`frameId` filter. They are duplicated because the package's exports map (`packages/workflows-ui/package.json`) doesn't expose `./screenshots` (only `serializeWorkflowData` is re-exported from the root). The cost is silent divergence: "Learned from" (`flowsApi.repetitions`) and the Task Page read the same stages, so if workflows-ui ever accepts another embedded format or changes the legacy `stage.screenshot` handling, this file keeps the old rule and the two screens show different captures with no failing test to catch it. Exporting the helpers from `@screenpipe/workflows-ui` (a one-line addition to the exports map, like `./model`) and importing them here removes the fork entirely.

**P3 — `apps/screenpipe-app-tauri/components/automation-flows/api.ts:264-265` — a 2xx response whose body fails to parse resolves to `null as T`.**

`const body = await response.json().catch(() => null); if (response.ok) return body as T;` — when the engine answers 2xx with an empty or non-JSON body, `request<Flow>` resolves `null` typed as `Flow`, and the crash surfaces later as an unrelated `TypeError` (e.g. `flow.status` in the Review Screen) instead of a `FlowsApiError` the Flows error UI can render. With today's engine this is unreachable — every 2xx handler returns `Json(...)` — which is exactly why it's a P3 and not higher, but this function is the PR's declared single seam (api.ts:5-8), and its error contract is otherwise airtight: network failures become `FlowsApiError("unknown")` (api.ts:260-263) and error bodies are decoded and typed. Throwing `new FlowsApiError("unknown", "empty response body")` when `body == null && response.ok` (still skipping it for `delete()`, which ignores the body) would make the seam total.
