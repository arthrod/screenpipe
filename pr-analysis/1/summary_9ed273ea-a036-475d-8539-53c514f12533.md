## Findings per focus

### eval-sop-chat.cjs — "grading rubric matches product promises" — P2 (pre-existing, unchanged by PR)

The eval's own PASS banner (line 49) promises "reopen without generation". The mechanism it tests: after `reload()` (line 34) click `Create SOP` (line 36), expect "Before you start" (line 37) and zero `Stop answer` buttons (lines 38-41). But the first pass's saved guide persists, so on the detail page the button renders `hasGuide ? "Open SOP" : "Create SOP"` (`packages/workflows-ui/src/workflows-app.tsx:730`; `hasGuide` from `platform.guides.load` at `workflows-app.tsx:661-665`). Empirically after reload the page shows **"Open SOP"** and no "Create SOP" (button dump from my probe: `Create SOP=0 Open SOP=1`), so the eval times out at line 36 and everything after (including the rubric's core reopen assertion) is unenforced. The product's actual reopen promise — "Open SOP" opens the saved guide without regenerating — is never tested. Not caused by this PR (fails identically at merge base; the label logic is unchanged context in the PR diff of `workflows-app.tsx`).

### eval-video-chat.cjs — "streaming/cancel behavior" — P2 (pre-existing, unchanged by PR)

The eval dies at line 25: `getByRole('button', { name: 'Heading', exact: true })` resolves to 4 elements (strict-mode violation) — the block-picker insert option (`packages/workflows-ui/src/document-block-editor.tsx:193`) plus per-step rich-text "Heading" format buttons (`packages/workflows-ui/src/rich-text.tsx:165`) inside the "Step 1/2/3 text block" regions. Everything after line 25 — including this slice's stated focus, the streaming/cancel sequence at lines 68-71 (`Create new video` → "Creating narration" → `Stop answer` → button restored) — never runs. I drove that cancel sequence manually at HEAD and it **works** ("CANCEL WORKS: Stop answer restored Create new video"), so the behavior is currently fine but completely unguarded: a cancel regression would ship uncaught by the one eval documented as covering it (`docs/pr-assets/desktop-video-sop/blocks/README.md:8`). Fix is to scope the locator to the insert menu (e.g. within the menu opened from "Add block after Guide summary", `document-block-editor.tsx:136`).

### eval-source-preview.cjs — "image loading and failure states" — P3 (pre-existing dead assertion)

PASSES at HEAD, and its image-loading half is real: line 19 asserts `img.complete && naturalWidth > 0` and it holds with this PR's `screenshots.ts` change (`isEmbeddedScreenshot` negative-frameId path, `packages/workflows-ui/src/screenshots.ts` diff — this fixture doesn't use it; it strips screenshots into evidence and resolves via `loadSourceScreenshot`, `app/preview/page.tsx:19-35`).
