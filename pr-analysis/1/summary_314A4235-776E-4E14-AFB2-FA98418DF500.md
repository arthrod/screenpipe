## What this slice changes

`n8n-catalog.ts` is a dev-time generator (`bun infra/automation-flows/n8n-catalog.ts`,
`n8n-catalog.ts:21`) that reads the running n8n container (`docker exec`,
`n8n-catalog.ts:33-37`) plus the repo's own ScreenPipe node classes
(`screenpipeTypes()`, `n8n-catalog.ts:227-237`) and emits two artifacts:

- `n8n-catalog.json` — the **check layer**: per node type, its versions, trigger
  flag, required credentials with display rules, and required parameters plus
  every parameter a display rule transitively reads (fixed-point loop,
  `n8n-catalog.ts:90-96`), each with the raw `show`/`hide` rules it carries
  (`rules()`, `n8n-catalog.ts:67-72`). Consumed by the engine via
  `include_str!` at `crates/screenpipe-engine/src/flow_checks.rs:25`, which
  also evaluates `@version` and `_cnd` rules (`flow_checks.rs:365-421`), so the
  raw-rule passthrough is a deliberate cross-language contract.
- `n8n-nodes.json.gz` — the **browsing layer**: an index of every type
  (switched-off ones flagged `off`) plus a per-type card of the latest version
  with trimmed parameters; deterministic bytes claimed via sorted keys and
  mtime-0 gzip (`n8n-catalog.ts:280-303`). Consumed line-by-line by
  `crates/screenpipe-engine/src/n8n_nodes.rs:137` — the one-line-per-entry
  output format (`join(",\n")`, `n8n-catalog.ts:281,295-298`) matches that
  parser.

`n8n-catalog.test.ts` pins: the catalog describes the image pinned in
`docker-compose.yml` (line 21-25); every demo-workflow node exists at its
version (27-33); excluded nodes are absent and ScreenPipe nodes present
(35-41); cross-layer invariants — usable index types ≡ check-layer keys at
their max version, every card resolvable including via `toolOf` twins (49-57);
switched-off types flagged, including synthesized tool twins of excluded nodes
(59-72); card contents for gmail/jira including nested fixedCollection
required fields and no icon/routing/HTML leakage (74-88); and a round-trip of
the four `CUSTOM.*` types comparing `group()`/`indexEntry()`/`detail()` output
against the committed artifacts (92-104).

## How it fits the whole PR

Automation Flows lets the chat build n8n workflows; this generator produces the
ground truth the engine checks those workflows against (`flow_checks.rs` head
comment) and the search/browse corpus the chat reads (`n8n_nodes.rs`). It is
the trust anchor for "refuses a Flow with an invented, disabled or incomplete
node" (`n8n-catalog.ts:7-9`), so silent wrongness here becomes wrong accept /
wrong refuse behavior in the product.

## Verification performed (this session)

- `bun test infra/automation-flows/n8n-catalog.test.ts` (repo root): **first
  run 8 pass / 1 fail** — `Cannot find package 'n8n-workflow' from
  .../ScreenPipe/ScreenPipe.node.ts` in the round-trip test; **immediate
  re-run: 9 pass, 0 fail, 1742 expect() calls**. `n8n-workflow` is installed
  at `packages/n8n-nodes-screenpipe/node_modules/n8n-workflow` and a direct
  `bun -e` import of the node file resolves from both the repo root and the
  package CWD, so I treat the first failure as a transient resolution/cache
  artifact, not a code bug; I could not reproduce it a second time.
- Malformed-input probes via `bun -e` against the exported `group`/`detail`:
  - `version` missing → `group().versions = [null]` (JSON), `latest` = `NaN`;
  - `version: []` → `versions: []`, `latest` = `-Infinity`;
  - `version: null` → `latest` coerces to `0`, versions JSON `[null]`;
  - `show: {"@version": [{_cnd:{weird:2}}]}` → parameter kept (fail-open);
  - `show: {"@version": ["3"]}` with version 3 → parameter silently dropped.
- Read the consumers to validate the parsed shapes: `flow_checks.rs:25,39,76`
  (`include_str!`, `Vec<f64>`, `.expect(...)` at first use) and
  `flow_checks.rs:365-421` (`@version`/`_cnd` evaluation, unknown op → `None`),
  and `n8n_nodes.rs:137` (line-based parsing).
- Listed `packages/n8n-nodes-screenpipe/nodes/`: exactly `ScreenPipe`,
  `ScreenPipeAiTrigger`, `ScreenPipeTrigger` — so `screenpipeTypes()` has no
  live problem today.

Not run: the generator itself (needs the n8n docker container up); gzip
byte-reproducibility across runs; a fresh regeneration diff against the
committed artifacts.

## Findings (posted; details in the comments file)

1. **P2** `n8n-catalog.ts:109` — no validation of `description.version`: a
   malformed entry writes `versions:[null]` (or `[]`) while the generator
   prints success, and the engine later panics at
   `flow_checks.rs:76` (`Vec<f64>` deserialization). Probed, not theorized.
   Loud failure belongs at generation time.
2. **P2** `n8n-catalog.test.ts:20` — the suite validates committed artifacts
   more than it pins extraction rules: `versionAllows` and the transitive
   closure have no synthetic tests; only the 4-type round-trip exercises the
   code. A generator regression passes until someone regenerates.
3. **P3** `n8n-catalog.ts:242-247` — any unexpected `nodes.json` in the image
   is silently prefixed `n8n-nodes-base.`; a future third package would be
   mislabeled and the check layer would then refuse its real type strings.
4. **P3** `n8n-catalog.ts:151-153` — `versionAllows` fails in opposite
   directions for malformed `@version` input (unknown `_cnd` op keeps;
   type-mismatched value silently drops). Probed.
5. **P3** `n8n-catalog.ts:230-234` — `screenpipeTypes()` assumes every entry
   under `nodes/` is a well-formed node package (no `withFileTypes` filter,
   class name must equal dir name). No live bug today.

## Noted but not posted (below posting threshold)

- `inContainer` interpolates found paths into `sh -c` via single quotes
  (`n8n-catalog.ts:251-252,268`); a quote in a container path would break
  confusingly. Input is the trusted pinned image, so hardening only.
- `indexEntry` calls `group(description)` (`n8n-catalog.ts:215`) just for the
  trigger flag, recomputing credentials/params per type; runtime is dominated
  by `docker exec` calls, so harmless.
- `group()` seeds `wanted` from all credentials' rule names including
  non-required ones (`n8n-catalog.ts:91`); over-inclusive is safe for the
  check layer.

## Quality signals worth keeping

Deterministic output by construction (sorted type keys, fixed key order,
mtime-0 gzip claim at `n8n-catalog.ts:299-300`); loud failure when the exclude
config cannot be found (`n8n-catalog.ts:253`); the tool-twin exclusion rule
(`n8n-catalog.ts:263`) is subtle but directly tested
(`n8n-catalog.test.ts:66-72`); the cross-layer invariant test (49-57) is the
strongest test in the file.
