Two findings:

**[P2] `crates/screenpipe-engine/src/automation_flows.rs:223-225` — the single global `write_lock` is held across the up-to-90-second unpublish wait, so one Flow that cannot stop freezes every operation on unrelated Flows.**

`RunningWait::default` polls n8n for up to 90 s before giving up (`automation_flows.rs:201-208`), and `deactivate_flow` takes `FlowsState.write_lock` *before* that wait (`automation_flows.rs:1545`, wait at `1554`) — same pattern in `delete_flow` (`1601-1608`) and `update_flow` (`1690-1698`). Every other state-changing route takes the same one lock (`activate_flow:1484`, `delete_flow:1584`, `set_dismissed:1648`, `create_flow:2038`, `create_from_task:2094`, `start_draft:1913`, `update_draft:1963`, `finish_draft:1994`, `health.rs:315`). So while one Flow has a hung execution — exactly the case the `user_stop` escape hatch anticipates — "Turn on" on a *different* Flow, dismissal, creation and draft steps all queue for up to 90 s with no response. The lock's stated purpose (`223-225`) is serializing store writes and the import-once guarantee; the same-flow exclusion the wait actually needs could be per-flow (or the global lock could cover only the store read-modify-write, re-checking the Flow's state after the wait), so a stuck Flow doesn't block the rest of the UI.

**[P3] `crates/screenpipe-engine/src/automation_flows.rs:641-651` — `send()` collapses n8n failure detail in two ways that the Review Screen and the chat skill then show the user.**

A non-JSON error body (a reverse-proxy 502 page, n8n dying mid-request) becomes `Value::Null` via `unwrap_or` at line 645, so the surfaced error is a bare "n8n answered 502" with nothing to act on; falling back to a truncated `response.text()` snippet when the body is not JSON would keep the cause visible. And every 401/403 becomes `412 n8n_unauthorized` (`648-650`), which the UI presents as "paste a valid API key" — when n8n refuses for a reason that is not the key itself (API access disabled for the user's role, an endpoint their plan gates), re-pasting the same key cannot fix it and the setup loop gives no hint why. Worth at least a distinct detail string for 403.
