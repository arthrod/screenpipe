## Docs review — `SPEC.md` + `automation-flows-spec.md` (hackathon spec slice)

Reviewed both spec files against the code this PR ships. The binding banner is present (`SPEC.md:3-7`, "This file holds the decisions and contracts the implementation follows…"), and of ~40 spot-checkable claims most match the implementation exactly (routes, error codes, constants, headers, node fields). The findings below are where the spec no longer matches shipped behavior, plus one appendix contradiction.

---

**P2** — `docs/automation-flows/history/hackathon/SPEC.md:277-283`

**The "Tool round trip through the AI proxy FAILS today" note is stale — the fix it prescribes is in this PR.** The note says the proxy's tool calls have no `id`, n8n replies with `tool_call_id: ""`, the proxy answers 400, and "Until then the demo workflow fails at the AI step for any email where the agent calls the tool". Shipped code does exactly what this paragraph asks for: `normalize_tool_calls` in `crates/screenpipe-engine/src/routes/cloud_proxy.rs:123-151` gives every `tool_calls[]` entry a unique `call_<uuid>` id and `type: "function"` (line 140) and sets `finish_reason: "tool_calls"` when missing (150-151), with a test at `cloud_proxy.rs:206`; the `chatgpt/<model>` path (which D21 makes the demo path) maps Codex `call_id`s to Chat-Completions tool-call ids both ways (`chatgpt_proxy.rs:238-253,459-476`). A reader of this binding decision log would believe the demo is broken at its core step. The adjacent security gap "the email body is quoted unescaped in the Jira wiki-markup description" (:297-298) is stale for the same reason — the shipped Jira body (`infra/automation-flows/workflows/novadesk-support-tickets.json:375`) is built from the AI's fields plus sender/date/subject and never quotes the email. Please refresh both to past tense or delete them.

**P2** — `docs/automation-flows/history/hackathon/SPEC.md:35`

**D10's verbatim French question texts don't match the shipped English UI — and the code comment claims they do.** D10 quotes « Les idées d'amélioration (comme NOVA-27) doivent-elles aussi devenir des tickets ? » / « Comment choisis-tu la priorité ? », but the shipped questions are English: `apps/screenpipe-app-tauri/lib/automation-flows/demo-task/detected-task.ts:44-47` ("Should improvement ideas (like NOVA-27) become tickets too?" / "How do you choose the priority?") — under the comment "D10: the only Clarification Questions, verbatim". This is part of a systematic French-vs-English drift: « Créer l'automatisation » (SPEC:15) vs "Create automation" (`packages/workflows-ui/src/workflow-questions.tsx:317`); D19's « n8n injoignable, tes Flows ne tournent pas » (SPEC:44,125) vs `N8N_DOWN_BANNER = "n8n is unreachable: your Flows are not running"` (`components/automation-flows/health-banner.tsx:16`); acceptance's « Activé par vous » / « Désactivé hors de Screenpipe » (SPEC:222-223) vs `labels.ts:32-34` "by you"/"outside screenpipe". `apps/screenpipe-app-tauri/gt.config.json` declares only `ja` beyond English, so French cannot render. The acceptance quotes are a dated record of the 2026-10-17 demo machine, which is fine — but D10, D19 and the user journey present French as the shipped strings. Either update the spec to the English strings or note that the UI moved to English after 2026-10-17; `detected-task.ts`'s "verbatim" comment should then point at the corrected text.
