## Focus-area verdicts (on the branch's unchanged copies)

- **Wire-format version compatibility (`lib.rs`)** — no change in the PR. The
  branch's re-export list (`crates/screenpipe-telemetry-wire/src/lib.rs:38-42`)
  lacks `build_starred_jsonl`/`StarredRow` only because it predates upstream
  #7677; after the required merge of `main`, upstream's version wins. The
  crate's own compatibility mechanisms (`serde(default)` on newer manifest
  fields, `parse_jsonl` skipping unknown `kind`s — `records.rs:509-521`,
  tested by `corrupt_lines_are_counted_not_fatal` at `records.rs:713-721`)
  are intact on the branch.
- **Manifest signature/identity handling (`manifest.rs`)** — no change in the
  PR. The manifest carries identity via `device_id` plus deterministic
  `compute_batch_id` (SHA-256 over device id, plaintext checksum, counts,
  cursors — `manifest.rs:85-100`) and an optional `stable_device_id`
  attribution field (`manifest.rs:68-69`). There are no cryptographic
  signature fields to regress; the unchanged test
  `manifest_wire_shape_has_no_encryption_fields` (`manifest.rs:154-178`)
  still passes.
- **PII redaction before encoding (`records.rs`)** — no change in the PR.
  Redaction happens upstream of this crate by contract: `FrameRow.text` is
  "Already PII-sanitized on the device if PII removal is enabled"
  (`records.rs:30-32`) and `accessibility_tree` is stored "with device
  privacy settings applied" (`records.rs:33-38`). The encode path
  (`build_jsonl_with_semantic_streams`, `records.rs:376-480`) does no
  redaction itself and was not modified, so no new PII exposure is
  introduced by this PR.
