### `apps/screenpipe-app-tauri/components/settings/__tests__/connection-credential-forms.test.tsx`

**[P2] `connection-credential-forms.test.tsx:251` — the n8n test only pins the happy path; nothing fails if secrets start being echoed into errors or back into the form.** The mock returns `ok:true` for every call (`:252-255`), so the component's error path is never exercised: `ConnectionCredentialForm` renders server-provided error strings straight into the DOM (`components/settings/connections-section.tsx:2666`, `:2673`, thrown/cleaned at `:2682`, rendered at `:2758`). Today that's safe — the client never interpolates the submitted credentials into the message and never logs them (read `handleConnect`/`handleDisconnect`, `connections-section.tsx:2648-2702`) — but a future change like including the request body in the error text, or `console.error`-ing it, would pass this suite. Likewise the mock returns `credentials: {}` (`:254`), so the property "a *stored* n8n API key is not echoed into the form" is untested on the frontend: `visibleConnectionCredentials` (`lib/utils/connection-credentials.ts:15-25`) is asserted only from the Rust side (`crates/screenpipe-connect/src/connections/n8n.rs:136-150`) and via `ConnectSection` in the hermes test (`:123-162`), never via `ConnectionCredentialForm` with a secret field. Since this suite exists precisely to pin the secret-handling contract, two cheap additions would close it: (a) render with `connected: true, credentials: { api_key: "n8n-key-sentinel" }` and assert `queryByDisplayValue("n8n-key-sentinel")` is null (mirroring `:159-161`); (b) make `/connections/n8n/test` respond with an error and assert the rendered error text does not contain the typed key.

**[P3] `connection-credential-forms.test.tsx:288` — guard the PUT lookup before dereferencing.** `expect(put?.[0]).toBe("/connections/n8n")` followed by `put![1]`: if Connect never fires the PUT, `waitFor` times out with "expected undefined to be '/connections/n8n'" instead of the clearer "expected undefined to be truthy" that the sibling test produces with its `expect(put).toBeTruthy()` guard (`:207-210`). Trivial consistency fix, better failure output only.
