## Findings

1. **[P2] Timezone-fragile test — fails on this machine, passes only east of UTC-2.** flows-tab.test.tsx:790 asserts `/Oct 17, .+ · Gmail, Jira$/` for a capture at `2026-10-17T02:05:41Z`, but `formatDate` (labels.ts:38-48) renders in local time with no `timeZone` option. Verified by running the suite:
   - `bun x vitest run --config vitest.config.ts components/automation-flows/__tests__/flows-tab.test.tsx` in `apps/screenpipe-app-tauri` under America/New_York (UTC-4): **1 failed, 69 passed** — failure at flows-tab.test.tsx:790, rendered text `Fri, Oct 16, 10:05 PM`.
   - Same command with `TZ=UTC`: **70 passed (70)**.
   The file itself shows awareness of the hazard (comment at flows-tab.test.tsx:280 picks 09:05Z "in any time zone from UTC-9 to UTC+14"); the repetition test's 02:05Z timestamps don't meet that bar (they fail from UTC-3 westward, i.e. all of the Americas). CI on a UTC runner stays green, so CI will not catch it. Posted as a review comment.

2. **[P3] The recovery the `flow_running` copy promises is never exercised.** "Try again in a moment" (flow-activation.tsx:18, flow-delete.tsx:18) is asserted as text at flows-tab.test.tsx:669 and :935, but no test clicks Pause / "Delete for good" a second time after the failure and asserts success, nor that the button is re-enabled. The activate path does check this (flows-tab.test.tsx:653 asserts `disabled === false`), so the pattern exists; a regression that left `busy` stuck true (losing the `finally` in flow-activation.tsx:87-89 or flow-delete.tsx:47-49) would pass this suite for Pause and Delete. Posted as a review comment.

3. **[P3] Background-read-failure test's "silent" assertion is string-specific.** flows-tab.test.tsx:1157 asserts `queryByText("Could not reach n8n")` is null; `queryByRole("alert")` would be null too here (health defaults to reachable, so no banner) and would prove silence against any future error surface. Posted as a review comment.

4. **[P3] `expect.anything()` for the repetitions second argument.** flows-tab.test.tsx:787 — the second arg is the `AbortSignal` (flow-learned-from.tsx:37); `expect.anything()` accepts any non-null value, so the abortability contract is unpinned (`expect.any(AbortSignal)` would pin it). No test covers the abort-on-unmount path (flow-learned-from.tsx:45). Posted as a review comment.
