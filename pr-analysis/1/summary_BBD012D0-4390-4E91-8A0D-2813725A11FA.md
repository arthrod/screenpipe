## What this slice changes

1. **All-captures grid → one-at-a-time carousel.** Base rendered every verified screenshot of a stage at once, expanded by
   default (`expanded = !reduced.has(capture.frameId)`, old line in diff). The head keeps one `EvidenceFigure` mounted
   (`workflow-step-evidence.tsx:78`), driven by `index`/`position` state (`:42-46`), with prev/next buttons and an
   `aria-live` counter (`:83-87`), arrow-key handling on the group (`:74-77`), and wrap-around modulo navigation (`:46`).
2. **Collapsed-by-default sizing.** Captures now render in a fixed 220px-high frame (`module.css:3,14`), enlarged only on
   request (`enlarged` Set keyed by frameId, `tsx:24,79`; `.figure.expanded` full-width, `module.css:15,17`). Base sized each
   image to its natural ratio capped at 360px and expanded by default. Intentional per the rewritten test "shows the verified
   screenshot in a compact frame, enlarges it on request".
3. **Missing-evidence handling.** The loading/failed/unavailable placeholder is a fixed 16:9 box of the frame height
   (`.figure .frameStatus`, `module.css:19`; rendered at `tsx:126-129`), replacing the base's measure-after-load
   `aspectRatio` state (removed `ratio` state in diff). Text states differentiate "Could not load…" / "Loading…" /
   "This screenshot is no longer available." (`tsx:127`); retry offered only on hard failure (`tsx:128`).
4. **Embedded fixture images fixed.** `isEmbeddedScreenshot` (negative frameId + valid `data:image/*;base64,` URL,
   `screenshots.ts:8-11`) now gates both recorder resolution (`tsx:114`) and the replay button (`tsx:80`): scripted
   negative-ID fixtures render their own pixels and never call `loadWorkflowScreenshot`/`openCapturedMoment`. Base resolved
   even negative-frameId captures through the recorder ("including legacy embedded images", base comment), which could only
   fail since "a negative frameId never names a recorder frame" (`screenshots.ts:5-7`). Covered by the new test "shows
   embedded fixture images from their own pixels, without recorder lookup or replay".
5. **Timeline label.** New optional `timelineLabel` prop (`tsx:17-23`), passed only when `platform.openCapturedMoment`
   exists; `workflows-app.tsx:729` sets it to "View in timeline" in creation mode (`:742-743` both call sites). Rendered
   through the new `RecordingButton` (`tsx:101-108`) with a visible label and a richer accessible name (`tsx:105-106`).
6. **CSS overflow work.** Caption text gets `min-width: 0; overflow-wrap: anywhere` (`module.css:23`) so long captions wrap
   inside the flex row; when paged, the caption reserves `padding-right: 104px; min-height: 32px` for the absolutely
   positioned nav (`module.css:11,24`). All colors stay on theme tokens (`--panel/--ink/--line/--soft/--muted`) — no
   hard-coded colors, so the dark-mode contrast problem flagged elsewhere on this PR (`workflows-app.module.css:337`, by
   coderabbitai) does not recur here.

Also removed with this redesign: the base's per-image select/reorder/hide editing (`onImageLayoutChange`,
`stage.imageLayout`). `rg -n "imageLayout|onImageLayoutChange" packages apps` returns nothing — clean removal, no dead code.

## Findings (details in comments file)

- **P2 — arrow-key navigation drops keyboard focus** when the focused control is inside the keyed figure (image button or
  the placeholder's retry button): `tsx:73-81` handles arrows for the whole group (keydown bubbles from descendants — the
  nav buttons depend on this), but the figure is remounted on every move (key `${frameId}:${timestamp}`, `tsx:78`), so the
  focused DOM node is destroyed and focus falls back to `body`. The in-code comment at `tsx:82` covers only the nav
  buttons, which live outside the figure; the tests only exercise the nav-button case.
- **P3 — coarse-pointer geometry:** `pointer: coarse` grows the nav buttons to 44×44 (`module.css:49`) → nav ≈126px wide
  and 44px tall, vs the 104px reserved padding and 32px caption band (`module.css:11,24`): caption text can run ~22px under
  the Previous button on touch devices.
- **P3 — `type="button"` missing** on the placeholder retry button (`tsx:128`); all sibling controls set it. Harmless today
  (no `<form>` ancestor anywhere in the package — verified by grep), latent submit if one is added.
- **P3 — labelled recording button can't shrink/wrap** (`module.css:44-45`: `flex-shrink: 0` + `white-space: nowrap`): a
  narrow portrait capture (`width: fit-content`) can leave the caption content box narrower than the ~100px "View in
  timeline" button, pushing it over the nav.

## Minor observations (not posted)

- The fixed 16:9 placeholder (391px wide at 220px height) is wider than many real captures (a portrait capture at 220px
  height is ~124px wide), so the *width* still jumps between captures even though the height is steady — the
  "keeps the page short and steady" comment (`tsx:121`) only holds vertically.
- `openRecording`'s default parameter `capture = screenshot` (`tsx:48`) is effectively dead: the only call without an
  explicit argument renders only when `screenshots.length === 0`.
- `enlarged` persists per frameId across navigation (enlarge capture 1, move away and back → still enlarged). The first
  carousel test asserts this, so it is intended.
