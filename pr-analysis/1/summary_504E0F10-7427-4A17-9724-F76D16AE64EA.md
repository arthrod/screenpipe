## What the files do (PR-head state)

- `crates/screenpipe-redact/src/adapters/rfdetr_mlx.rs` — RF-DETR-Nano image-PII detector via the
  pure-Rust MLX runtime, Apple-Silicon-only, behind the `mlx-mac` cargo feature
  (`Cargo.toml:114`, forwarded from the engine as `rfdetr-mlx`,
  `crates/screenpipe-engine/Cargo.toml:192`). Real implementation in a cfg'd `imp` module
  (`rfdetr_mlx.rs:223-420`); stub returning `RedactError::Unavailable` otherwise
  (`rfdetr_mlx.rs:427-455`). Runtime-gated to macOS ≥ 26 via `sw_vers`
  (`rfdetr_mlx.rs:44,55-76`). Downloads `rfdetr_v9.safetensors` (~108 MB) from a pinned HF URL,
  verifies SHA-256, atomic-rename into place (`rfdetr_mlx.rs:137-199`).
- `crates/screenpipe-redact/src/adapters/tinfoil.rs` — text redactor against the Tinfoil
  confidential-compute enclave; SEV-SNP attestation + Sigstore + TLS SPKI pinning via the
  `tinfoil` SDK (pinned by rev, workspace `Cargo.toml:142`); cached attested client with a 12 h
  re-attest cadence and reactive invalidation on cert-drift-looking errors.
- `crates/screenpipe-redact/src/adapters/tinfoil_image.rs` — same enclave, image modality: sends
  the frame file raw-base64'd to `POST /image/detect` with threshold + label allow-list.

## Focus-area verdicts

### MLX: guarded builds and fallbacks — guards are correct, but nothing in CI compiles the feature-on path

- Cfg gating is mutually exclusive and exhaustive (`rfdetr_mlx.rs:30,223,422,427,441`); the stub
  path compiles everywhere: `cargo check -p screenpipe-redact` → Finished in 25.74s (ran).
- Engine fallback is clean and opt-in: MLX is only attempted with
  `SCREENPIPE_ENABLE_EXPERIMENTAL_RFDETR_MLX` set, `ensure_model_present()` failure or `load()`
  failure each fall through to the ONNX adapter with an info log
  (`crates/screenpipe-engine/src/bin/screenpipe-engine.rs:2352-2407`); download is skipped
  entirely on unsupported runtime (`rfdetr_mlx.rs:138-143`).
- **Gap:** CI never compiles the `mlx-mac` path. `ci.yml:121` tests with default features
  (stub only); `style.yml:101-107` clippy also default features; only release builds compile it
  (`release-app.yml:200`, `release-cli.yml:146`) and they run no tests. I attempted
  `cargo check -p screenpipe-redact --features mlx-mac` locally on this macOS aarch64 host and it
  fails in `mlx-sys`'s build script: "cannot execute tool 'metal' due to missing Metal Toolchain"
  — so the ~200-line `imp` module could not be compile-verified in this review either, and a typo
  there would only surface in release builds. Suggested: a macOS-aarch64 CI job (or release-pre
  check) running `cargo check -p screenpipe-redact --features mlx-mac`.

### Tinfoil text: network error handling — solid

- Per-request timeout (`tinfoil.rs:372`, 60 s, rationale documented at 92-99); short-circuit below
  `MIN_FILTER_CHARS` avoids the round-trip and attestation entirely (test
  `short_text_bypasses_round_trip` passes); failures bubble up, never silently returning
  unredacted input (`tinfoil.rs:55-56,381-405`); non-success → `RedactError::HttpStatus`
  (`tinfoil.rs:402-406`); JSON decode errors map through `RedactError::Http(#[from] reqwest::Error)`
  (`error.rs:10-11`).
- Reactive re-attestation on cert drift (`looks_like_attestation_drift`,
  `tinfoil.rs:312-324`) matches some generic transient TLS strings ("tls handshake eof",
  "peer closed connection without sending TLS close_notify") — false positives cost one 1-2 s
  re-attest, which the code comment explicitly accepts (`tinfoil.rs:310-311`). Not posted; it is
  documented and bounded.
- One posted concern (shared with the image adapter): the full non-success response body is
  embedded into `RedactError::HttpStatus` and its `Display` (`error.rs:14-18`) lands in worker
  logs; a FastAPI 422 echoes the offending `input` value, which for `/filter` is the OCR text —
  and for `/image/detect` (below) can be the entire base64 screenshot. Truncate before embedding.

### Tinfoil image: payload privacy — payload is minimal; two defense-in-depth gaps posted

- What leaves the machine: raw frame-file bytes (base64), threshold, label allow-list, optional
  Bearer (`tinfoil_image.rs:243-252,283-293`). No paths, timestamps, or device identifiers.
  URL is hardcoded `https://` (`tinfoil_image.rs:284`); `strip_scheme_and_path` prevents a
  config-supplied scheme downgrade (`tinfoil.rs:329-338`). Bearer header is `set_sensitive`
  (`tinfoil_image.rs:155`). Sending the pixels is inherent to server-side detection, and the
  module doc states the threat model (`tinfoil_image.rs:12-28`).
- EXIF risk checked: frames on disk are freshly JPEG-encoded by screenpipe itself
  (`crates/screenpipe-screen/src/core.rs:22,50`, `image` crate `JpegEncoder`, quality 80) — no
  EXIF/metadata side-channel in the bytes that are sent.
- Posted: (1) `DetectRequest` derives `Debug` **including `image_b64`**
  (`tinfoil_image.rs:243`) — one accidental `debug!(req = ?req)` dumps a full screenshot into
  logs; the text sibling deliberately does not derive Debug on `FilterRequest`
  (`tinfoil.rs:127-137`). (2) unbounded response body into error logs (above).
