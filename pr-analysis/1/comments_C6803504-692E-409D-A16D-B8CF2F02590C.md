One nit from the new wiring:

**P3 (robustness) — `crates/screenpipe-core/src/agents/pi.rs:918`**
The new `skill_files` loop writes `skills_root.join(name).join(file)` without a `create_dir_all`, so it silently depends on the parallel `skills` list containing the same name (its loop creates the directory at `pi.rs:906`). If the two lists ever drift — someone adds a linked file for a skill not in `skills`, or typos the name — `ensure_screenpipe_skill` hard-fails session setup with a bare `NotFound` from this `?`, which reads as a mystery error far from its cause. A one-line `std::fs::create_dir_all(skills_root.join(name))?` before the write (or a `debug_assert!` tying the lists together) makes each entry self-sufficient.
