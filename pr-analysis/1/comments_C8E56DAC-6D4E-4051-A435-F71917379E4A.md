## Review: demo shortcut listener (component + test)

**[P2] `apps/screenpipe-app-tauri/components/automation-flows/__tests__/demo-shortcut-listener.test.tsx:70-81` — the test never asserts listener teardown.**

The component's cleanup (`demo-shortcut-listener.tsx:39`) is the only thing preventing a leaked window-scoped listener — and a leaked listener keeps a stale `press` closure alive, so an unmounted subtree could still run the demo on a shortcut press. But no test unmounts the component and checks the fake bus lost its listener, so a regression here (effect returning no disposer, or a broken unlisten) passes the suite green. Please add a case like: `const { unmount } = render(<DemoShortcutListener />);` → wait for `bus.listeners.length > 0` → `unmount()` → flush microtasks (the unlisten is promise-based, so the removal lands on a later tick) → `expect(bus.listeners.length).toBe(0)` → `bus.emitTo("home", DEMO_SHORTCUT_EVENT)` → `expect(press).not.toHaveBeenCalled()`. Note on the file's other focus: it correctly does not simulate raw key sequences — the chord is captured natively in `src-tauri/src/shortcuts.rs` and this layer only ever sees the Tauri event, so the fake-bus dispatch (test:8-23, mirroring Tauri's `match_any_or_filter`) is the right boundary; teardown is the missing half.

**[P3] `apps/screenpipe-app-tauri/components/automation-flows/__tests__/demo-shortcut-listener.test.tsx:44` — mocked `press` never rejects; the error path and the mock-mode guard are untested.**

The listener wraps the handler with `press().catch(error => tell("Demo not started", ..., true))` (`demo-shortcut-listener.tsx:37`), which is the user-visible failure surface of this component, and the `NEXT_PUBLIC_SCREENPIPE_WEB_DEV === "mock"` early return (`demo-shortcut-listener.tsx:23`) is what keeps the browser-mock dev loop from touching Tauri. Neither is exercised: the mock is `vi.fn(async () => ({ ignored: true }))` and no test sets the mock env. Two cheap cases would close it: one where `press` rejects (assert the destructive toast / `tell` was called with "Demo not started"), and one asserting that in mock mode no listener is registered (`bus.listeners` stays empty).
