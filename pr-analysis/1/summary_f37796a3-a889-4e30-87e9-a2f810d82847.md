# PR #1 review — slice: `apps/screenpipe-app-tauri/lib/automation-flows/demo-task/detected-task.ts`

Focus assigned: **detection heuristics — false-positive risk on ordinary screens becoming "detected tasks".**

## What this slice is

New 218-line file (`git diff origin/main...HEAD` shows it added with 2 sibling files under `demo-task/`). It is **not** a detection heuristic: it is fully scripted demo data. `buildDetectedTask()` (`detected-task.ts:134-218`) fabricates a complete `WorkflowMap` — "Turn bug emails into Jira tickets" with three hand-authored repetitions, evidence captures, timings, procedure steps, and quality scores. `notificationPayload()` (`detected-task.ts:28-41`) builds the "Repetitive task detected" notification, and `invisibleMark()` (`detected-task.ts:23-25`) appends zero-width characters so the body defeats the notification server's same-title+body repeat gate. Consumers (context, read-only): `lib/automation-flows/find-automation.ts` (installs the task into the **real** catalog via `saveWorkflowAnalysisToDisk` and posts the payload to `/notify`), `lib/automation-flows/demo-shortcut.ts` (⌃⌥⌘D handler), and `infra/automation-flows/demo` (CLI twin).

## How it fits the PR

This is the demo data layer of the Automation Flows feature (hackathon demo, SPEC "Demo data" D8/D10 per the file header, `detected-task.ts:4-10`). The PR's detection story elsewhere in the codebase is real (engine `workflow_catalog.rs`, review-notification loop `src-tauri/src/notifications/workflow.rs`); this file exists so the demo can show a detected task without any detection running — `find-automation.ts` header states: "Demo contract (AGENTS.md, Hackathon mode): no detection runs".

## Findings (posted; details in comments_f37796a3-a889-4e30-87e9-a2f810d82847.md)

1. **P1 — trust markers with no demo provenance, fully eligible for real pipelines** (`detected-task.ts:194,166,205-216`). The fabricated task claims `confidence: 0.9`, `visualVerified: true` (even for OCR-matched recorder frames), `catalogStatus: "current"`, `lastReviewedAt: now`, and `"good"` quality with 100% coverage. `WorkflowMap` has no demo/source field (`packages/workflows-ui/src/model.ts:160-200`), so once installed into the real catalog nothing downstream can distinguish it from a genuine detection. Verified eligibility for the real review-notification loop: `workflow.rs:34-46` names every catalog ID in `workflow_ids` and `supported_steps` counts this task's 3 procedure stages; loop wired at `main.rs:2403`. `rank: 1` (`detected-task.ts:180`) puts it first for Flow creation. This is the concrete form of the assigned focus: an ordinary screen (any production machine — the chord registers unconditionally, per the existing coderabbitai comment on `shortcuts.rs:527-536`, which I deliberately do not duplicate) gets a "detected task" for work that never happened, which can drive a real Flow against the user's own Jira.
2. **P3 — `screenshotCount: -embeddedId`** (`detected-task.ts:213`) is arithmetic by side effect; `EVIDENCE_CAPTURES.length` says the same thing safely.

Deliberately **not** posted (already on the PR): the "notification about work the user never did" wording and the always-registered ⌃⌥⌘D chord (coderabbitai on `src-tauri/src/shortcuts.rs:527-536`); demo-shortcut production gate (same thread).
