## Findings in my slice (posted, all P3)

1. **FlowRun fixtures omit the required `retried` field** — flows-tab.test.tsx:390-395
   and 423-430 annotate with `FlowRun` but omit `retried`, which is required
   (api.ts:69-80, field at api.ts:79). The retry-suite fixtures do set it
   (flows-tab.test.tsx:465, 474). No runtime effect (`flow-activity.tsx:103`
   treats `undefined` as falsy, so failed run e4 in the D18 list renders a
   Retry button the test never asserts about — the fixtures under-specify the
   scenario they paint). Root cause: tests are excluded from typechecking —
   `apps/screenpipe-app-tauri/tsconfig.json` excludes `**/__tests__/**`,
   `**/*.test.ts(x)`, so the `: FlowRun` annotations are never checked; vitest
   does not typecheck either. PR-wide pattern worth knowing: type annotations
   inside every new test file in this PR are decorative.
2. **Recovery path under-asserted** — flows-tab.test.tsx:249-250 asserts the
   row reappears and `calls === 2`, but never asserts the unreachable-banner
   alert is gone, so a stale banner over a recovered list would pass.
3. **Hard-coded calendar dates in assertions** — flows-tab.test.tsx:281 (also
   419, 592) hard-code "Sat, Oct 17" with a guard comment naming a safe TZ
   band. Correct within the band, but the pattern already broke at :790 in the
   same file; deriving the expected local date from the fixture would remove
   the whole class of failure.
