**`docs/automation-flows/history/flows-round-two/issues/12-retry-a-failed-run.md:38` — P1 (contradicts the shipped security policy)**

A reader building on this doc would either expose a retry path the code deliberately refuses or misdiagnose the refusal as a bug. Please rewrite the paragraph to the current policy (and note « Relancer » is now `Retry`, `flow-activity.tsx:131`). Everything else in the doc matches `retry.rs`: 404 `run_not_found` / 409 `run_not_failed` (retry.rs:39-52), 180 s → 504 `retry_still_running` (retry.rs:26,100), 20 s client timeout overridden (automation_flows.rs:258 vs retry.rs:94), `loadWorkflow` only when published or reviewed (retry.rs:54-61) — verified by `cargo test -p screenpipe-engine --test automation_flows_test` → 107 passed, including all six retry tests the doc names.
