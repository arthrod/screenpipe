## How it fits the PR

This suite is the executable spec for the demo Flow; the duplicate-safety story it
locks down:

1. **Search key == create key** — the `mail-<8 hex>` label the search JQL filters
   on (:553, :556-558) is the same label the create request puts on the ticket
   (:525). I verified in `novadesk-support-tickets.json` that both the
   "Find the ticket for this email" and "Create the Jira ticket" nodes inline the
   identical FNV-1a expression over `id → messageId → from|date|subject`.
2. **Found → end silently** — "Ticket already created?" yes-branch has no
   outgoing connection (:570); the JSON gate is `($json.issues ?? []).length > 0`
   (number gt 0, fail-open to create on a malformed `{}` response, asserted :574).
3. **Nothing else creates** — abstention branch is a graph dead-end (:249-257),
   `type: "none"` stops at the gate (:334-343), and the create request is a fixed
   body the AI cannot shape — no `$fromAI`, no Set nodes (:376-382).
4. **Replay safety** — failed runs are saved so n8n Retry re-feeds the email
   through the search (:95-100, D17); the deterministic label makes the replay's
   search find the earlier ticket (:526-528).
