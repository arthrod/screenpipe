### [P1] SKILL.md:179 — the worked example quotes a `labels` expression that does not exist in the NovaDesk Flow

> In the NovaDesk Flow, the node « Create the Jira ticket » (`httpRequest`) builds the Jira issue in `parameters.jsonBody`, which holds `labels: [ $json.output.label ]`. Change it to `labels: [ $json.output.label, 'auto' ]` …

The shipped demo workflow (`infra/automation-flows/workflows/novadesk-support-tickets.json`, node "Create the Jira ticket") has no `$json.output.label` anywhere in its jsonBody (zero occurrences; checked by parsing the file). Its labels array is:

```js
labels: [ o.label, (e => 'mail-' + /* FNV-1a hash of the email id/messageId/from|date|subject */)( $('New support email').item.json ) ]
```

where `o` is a local binding for the parsed AI answer inside the same expression, and the second entry is the per-email dedup key that must survive the edit. An agent following the skill's only worked "Change a Flow" example will search for an expression that is not there, and the "Change it to" instruction cannot be applied as written — the failure mode the skill itself worries about (rule 3: change only what was asked; never retype the JSON, SKILL.md:157). Please quote the real expression and say to append `'auto'` to that array, e.g. "which holds `labels: [ o.label, 'mail-…' ]` (the AI-chosen label and a dedup label); append `'auto'` to that array". This is the skill's canonical example, so the mismatch propagates to every agent that teaches itself from it.

### [P2] SKILL.md:81 — the `status` enumeration omits `dismissed`

> `status` is `draft` (never activated), `active`, `paused` or `needs_review` (changed since its last activation).

`derive_status` in `crates/screenpipe-engine/src/automation_flows.rs` also returns `"dismissed"` for a Flow the user set aside (`record.dismissed`), and `POST /:id/dismiss` / `/:id/restore` are real routes (`automation_flows.rs:298-299`). A dismissed Flow shows up in `GET /automation-flows` with a status this line says cannot exist, so an agent matching names/statuses for the user (e.g. « Delete a Flow », SKILL.md:330) can misreport what the Flow is. Add `dismissed` (set aside by the user until restored) to the list.
