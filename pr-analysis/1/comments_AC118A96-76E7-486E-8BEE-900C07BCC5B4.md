## Performance / rendering (pre-existing)

- **P2** `apps/screenpipe-app-tauri/components/activity-ledger.tsx:2202-2272` — Rendering has no pagination or virtualization: every entry in the selected range becomes a full interactive `<article>` (tooltip provider, icon components with retry timers). The design is intentional — `activity-ledger.test.tsx:1877-1899` asserts there is no "Generate more results" control — so this is only a risk while the generator's per-range entry count stays small, but on the 7d/custom presets a dense history renders hundreds of rows with nothing bounding initial render cost. If entry volume grows, day-level lazy rendering or windowing is the mitigation that doesn't break the pinned no-append design.
- **P2** `apps/screenpipe-app-tauri/components/activity-ledger.tsx:534-535` (with `:522-683`, `:2245`) — Artifact matching is O(entries × intervals): each rendered entry's `artifactsForHistoryEntry` walks the entire range-wide `ledgerIntervals` array and re-parses `interval.start_at`/`end_at` (and each evidence `occurred_at`, `:552`) with `new Date()` per pair. The per-entry `useMemo` (`:1182-1185`) doesn't help the total — every fetch or generation cycle costs E×I string parses on the main thread. Pre-parsing the intervals once when the fetch resolves (or sorting by `start_at` and scanning only the overlapping window) removes the quadratic factor.
- **P3** `apps/screenpipe-app-tauri/components/activity-ledger.tsx:438-450` — `formatEntryTime` and `formatEvidenceTime` construct a fresh `Intl.DateTimeFormat` on every call, and `formatEntryTime` runs in render for every entry (`:2231`); formatter construction is one of the more expensive Intl operations. Module-level cached formatters (locale-keyed) would cut per-render work across large lists. Same pattern, lower volume: `formatDay` (`:1296`), `formatPreviewRange` (`:862-865`).
- **P3** `apps/screenpipe-app-tauri/components/activity-ledger.tsx:1303-1310` — `groupByDay` rebuilds each day's array on every entry (`[...(groups.get(key) ?? []), entry]`), which is O(n²) allocations for a large day group; pushing into a mutable array keyed in the map is equivalent and linear.
- **P3** `apps/screenpipe-app-tauri/components/activity-ledger.tsx:1290-1301` — `formatDay` detects "Yesterday" via `day === today - 86_400_000` on local-midnight timestamps; on DST-transition days the gap between local midnights is 23 or 25 hours, so the previous day renders as a weekday name instead of "Yesterday" (cosmetic; compare calendar dates instead of millisecond difference).
- **P3** `apps/screenpipe-app-tauri/components/activity-ledger.tsx:1568-1573` — Any non-ok or failed `/activity-ledger` response is silently converted to `{intervals: []}`, so on a custom range wider than the engine's 31-day cap (`routes/activity_ledger.rs:129-131`) entries render with no artifact icons and no explanation, and no test covers that range. Worth at least a debug-level signal or a test pinning the degradation; I did not verify how `/activity-summary` handles the same range, so the claim is scoped to the ledger artifacts call.
