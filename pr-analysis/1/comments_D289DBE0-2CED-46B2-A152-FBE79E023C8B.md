**P2** | `infra/automation-flows/import-workflow.sh:29` — the script dies silently when Docker or the n8n container is down.

`active_ids="$(docker exec "$container" n8n list:workflow --active=true --onlyId 2>/dev/null)"` sends docker's stderr to `/dev/null`, so when the daemon isn't running or `automation-flows-n8n-1` doesn't exist yet, the only diagnostics are swallowed; the failed substitution makes the assignment fail, and `set -euo pipefail` (line 13) then aborts the script with **zero output** (I verified this abort-on-failed-substitution behavior locally: `bash -c 'set -euo pipefail; x="$(echo out; false)"; echo REACHED'` exits 1 printing nothing). "n8n isn't started yet" is the most common state for someone following the Quick start, and the demo runbook (`docs/automation-flows/history/hackathon/HANDOFF.md:24`) has presenters run this script — a silent failure there is exactly what you don't want. Please add an explicit container check before this line, e.g. `docker container inspect "$container" >/dev/null 2>&1 || { echo "error: container $container not found; start n8n first (README Quick start step 1)" >&2; exit 1; }`, keeping the `2>/dev/null` for n8n CLI noise only.

**P2** | `infra/automation-flows/import-workflow.sh:36` — re-importing a switched-off workflow silently destroys edits made in n8n.

The active guard (lines 29-33) only refuses to overwrite a workflow that is currently **running**. For a workflow that is off, `docker cp` + `n8n import:workflow` replaces n8n's copy in place with no notice — including any changes the user made in the n8n editor — even though the README's design rule 1 says "n8n is the source of truth" and rule 2 says edits happen in n8n. Concretely: a user pauses the Flow, tweaks a step in n8n, and anyone running this script (it's the documented post-pull step) wipes the tweak without a word. Since the header already promises in-place update, the fix can stay cheap: before `docker cp`, run `n8n export:workflow --id="$id"` and compare (or simply print a "replacing existing workflow $id" notice, or refuse with a `--force` escape when the existing export differs). The stated goal — not clobbering existing workflows silently — currently holds only for the active case.

**P3** | `infra/automation-flows/docker-compose.yml:22` — hard-coded `Europe/Paris` timezone for every user of the Quick start.

`GENERIC_TIMEZONE` and `TZ` are pinned to `Europe/Paris`, and this compose file is the README's general Quick start (README.md:134-138), not just the hackathon demo setup — so any user's schedule/cron-type n8n triggers will fire on Paris time with nothing telling them so (interval- and event-based triggers are unaffected). Suggest `${TZ:-Europe/Paris}` for both entries (compose interpolates from the shell environment with no `.env` needed), or a comment stating the choice is demo-specific.

**P3** | `infra/automation-flows/import-workflow.sh:19` — a missing or invalid workflow file fails with a bun stack trace instead of a message.

`file="${1:-...}"` (line 16) is never checked to exist, and the inline bun one-liner both reads and parses it; a typo'd path or non-workflow JSON aborts under `set -e` with bun's raw stack trace as the only explanation.
